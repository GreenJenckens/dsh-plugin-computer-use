# OCR accuracy — v0.4 report

**Date:** 2026-11-04 · **Engine:** Windows.Media.Ocr (en-US + ru) · **Dataset:**
12 images × 3 lines = 36 rendered lines (`plugin/dsh-plugin-computer-use/test/fixtures/ocr`)

## Method

- Offscreen WinForms/System.Drawing render, ClearTypeGridFit, 96 DPI: Segoe UI and
  Consolas at 9/11/14/18 pt, light and dark themes, 4 variants of RU prose, EN
  prose and `0O1Il5S`-style code lines.
- Eval seam: `ocr { _image }` is accepted only with `DSH_CU_OCR_EVAL=1`; the
  production `ocr` action never accepts a file path.
- Config grid: `ocrScale` 1/2/3 × engine `ru`/`en-US`; boxes off; text
  normalized to NFC + collapsed whitespace. CER/WER are micro-averaged over the
  concatenated text; `0→D` is counted with a deterministic Levenshtein
  backtrace. Full JSON: `docs/v0.4-ocr-results.json`.

## Results (12 images, concatenated 36 lines)

| Config | CER | WER | 0→D | Exact |
|---|---|---|---|---|
| scale 1, ru | 19.79% | 53.18% | **4** | 0% |
| scale 1, en-US | 27.09% | 51.69% | 0 | 0% |
| **scale 2, ru (default)** | **16.00%** | **44.94%** | **0** | 0% |
| scale 2, en-US | 23.65% | 44.94% | 0 | 0% |
| scale 3, ru | 18.04% | 45.32% | 0 | 0% |
| scale 3, en-US | 23.09% | 42.70% | 0 | 0% |

## Findings

1. **The known 0→D error is real at `ocrScale:1`** (4 substitutions, ru engine)
   and **disappears at the default 2×/3×** on this dataset. Keep 2× as the
   default; document that 1× is unsafe for digits/IDs.
2. **`0O1Il5S` is visually ambiguous** even at 18 pt in Segoe UI/Consolas: the
   engine returns `001115S`/`001115S` variants. No preprocessing can restore
   `O` vs `0` or `I/l` vs `1` reliably; this is an engine/font limit, not a
   tuning miss. Do not gate exact-match on such codes.
3. **RU prose is materially better than the combined CER suggests**: most errors
   in the combined metric come from the ambiguous code line and line merging.
   The engine also lowercases sentence-initial Russian words (`Итого`→`итого`),
   a case-only error no preprocessing fixes.
4. **Scale 2 is the best combined config** (16.00% ru / 23.65% en); scale 3 adds
   latency without a measurable win. The grayscale/contrast/pad and
   bicubic-vs-nearest grid was **not evaluated in v0.4**; we therefore do not
   claim a preprocessing win. This is the plan's allowed report-only branch.
5. **Oversize bug fixed:** Windows OCR rejects images above 10 000 px. A 4K
   window at `ocrScale:3` previously failed; v0.4 clamps the effective scale and
   reports `clamped=1`, verified with an 11 000×200 fixture.

## Limits

- 36 lines is a regression harness, not a benchmark; no claim against hosted
  vision models.
- No real-screenshot 0→D sample, no 4K/125%/150% hardware, no per-language
  routing in production (the caller chooses `ocrLang`).
- **P6 acceptance waiver:** CER at scale 2 is 16.00% ru / 23.65% en, not the
  ≤5% target; exact-match is all-or-nothing per image (0%); p95 latency was not
  measured. Accepted as **report-only**; only 0→D=0 at scale 2/3 and the oversize
  clamp are release claims.
- The dataset is synthetic and contains no secrets.
