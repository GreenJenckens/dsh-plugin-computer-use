# v0.4.1 — activity indicator and human confirmation

**Date:** 2026-11-04 · **Status:** implemented and manually verified on the live DSH desktop.

## What the user sees

When the `computer` tool is used:

- a blue/cyan **edge glow** (10 px line + 26 px soft glow) on the primary screen;
- a **cursor ring** that follows the pointer;
- a top-center banner **“DeepSeek Harness использует ПК”** with the hint
  `Ctrl+Alt+Shift+Q — отменить управление`;
- after ~15 s without a new operation everything fades out.

`Ctrl+Alt+Shift+Q` toggles pause/resume. In pause the glow/ring turn red, the
banner reads **“Управление приостановлено”**, and the bridge rejects every
operation until the hotkey is pressed again.

Consequential actions show a **human confirmation dialog**:

- terminal/interpreter typing;
- password-field writes/typing;
- buttons whose name/automationId matches `оплат`, `оплатить`, `купить`,
  `оформить`, `заказать`, `удалить`, `отправить`, `перевести`, `подтвердить`,
  or built-in `pay/payment/purchase/buy/checkout/submit/send/delete/remove/
  uninstall/format/transfer`;
- buttons: **Разрешить** / **Запретить**, 30 s countdown, Esc denies;
- without an answer the action is denied, not executed.

Windows with titles `DSH-CU-*` (glow, banner, cursor, dialog) are
`WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`, are filtered from
`windows.list`, and are rejected as explicit targets.

## Configuration

```yaml
config:
  indicator: true          # overlay + dialog
  confirm: consequential   # ask on class C; "never" = full access without dialogs
  confirmKeywords: [оплат, оплатить, купить, оформить, заказать, удалить, отправить, перевести, подтвердить]
```

- `confirm: "consequential"` + `indicator: true` → ask important actions.
- `confirm: "never"` → full access, no dialogs (explicit opt-in).
- `indicator: false` + `confirm: "consequential"` → deny class C without a dialog.

  - ask-mode protocol: request file → human response → action executes;

## Limits

- The confirmation is **on-desktop**, not a tamper-proof approval channel: the
  agent runs on the same desktop and a blind click at dialog coordinates is not
  technically impossible. The overlay is hidden from selectors, not from pixels.
  For a strict boundary use a VM/low-privilege user or DSH approval policy.
- Indicator is primary-monitor only; multi-monitor glow is not implemented.
- Full takeover (hand mouse to the human and back) is not implemented; the
  hotkey only pauses/resumes the agent.
- Keyword matching is heuristic and configurable; it can miss localized or
  unusual labels and can over-match. Add your own `confirmKeywords`.
