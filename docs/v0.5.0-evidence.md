## What was borrowed

`computer-user` is a strong DSH-native implementation with a different shape:
21 separate tools, a takeover pill, `/computer` session approval, stale-safe
locators, `computer_wait`, `computer_doctor`, optional CDP browser inspection and
a settings card. We kept the one-dispatcher-tool design and adopted the pieces
that fit its schema budget:

| Feature | v0.5.0 behaviour |
|---|---|
| Runtime modes | `mode: auto | readonly | disabled` in config; checked before the host is contacted. `readonly` permits observation only; `disabled` rejects all. |
| `observe.wait` | Poll every 250 ms for hwnd, title substring/regex or element selector; timeout 200–60 000 ms; no side effects. |
| `diagnostics` | PowerShell/UIA/OCR/monitors/temp/indicator/mode self-check; no window titles or typed text. |
| `expectedWindow` | `screenshot`/`ocr` refuse when the foreground hwnd changed, so a stale observation cannot be captured. |

Not adopted: 21-tool surface (kept one tool), takeover pill (our glow/banner +
`Ctrl+Alt+Shift+Q` already covers it), `/computer` session approval (our
`confirm` gate and modes cover the safety need), CDP browser lane, settings card,
output-guard text filter, and `tool_mode=lite`.

## Limits

- `mode` is config-only; there is no `/computer` chat approval or settings card.
- No transparent mouse-handoff takeover; `Ctrl+Alt+Shift+Q` pauses/resumes.
- Confirm dialog is on-desktop, not tamper-proof.
- Element `i=` indices remain per-walk; stable locators are still a v0.6 candidate.
- 2 monitors / 125–150% remain mathematically validated, not hardware-validated.
- OCR remains report-only (CER 16% ru / 23.65% en, 0→D=0 at scale 2/3).
